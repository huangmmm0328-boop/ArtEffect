# 给开发者的总指令

请把本文件作为 GAME ART INTELLIGENCE V2.0 的唯一总需求书，基于现有网站和 GitHub 仓库进行渐进式改造。

**本次不是要求一次性把所有功能做完。必须按 P0 → P1 → P2 → P3 的顺序实施，并在每个阶段完成验收后再进入下一阶段。**

## 不可违反的开发原则

1. **先备份，后修改。** 先检查当前线上网站、GitHub 仓库、部署方式、页面、游戏资料、图片和 GIF；建立 V2.0 分支或独立备份。不得直接覆盖当前生产站点。
2. **先验证数据源，再写采集器。** 必须先取得一份真实、当前可访问、允许使用的数据样本，核对字段、平台、榜单、日期、覆盖深度和授权范围，再开发对应适配器。
3. **先做真实数据，再做趋势预测。** 不得使用模拟数据冒充正式市场数据，不得在没有历史记录时展示虚构的 7/30/90 日曲线。
4. **先统一游戏档案，再做页面。** 每款游戏只维护一份主档案；榜单、搜索、趋势、用户研究、美术研究和特效研究都引用同一份档案，不得重复录入相同内容。
5. **市场机会与未来预测是网站主线。** 美术截图、风格和特效仍然保留，但必须服务于市场判断、用户需求、吸量创意和研发建议，不再作为网站唯一主线。
6. **免费优先。** 不购买 MomoRank Pro/API、DataEye、AppGrowing 付费套餐、QuestMobile 等商业服务；不使用付费 API。若某来源免费权限不足，标记“受限／待接入”，改用其他免费来源或人工文件导入。
7. **没有自有抖音广告账户。** 不开发自有抖音广告账户报表，不要求用户注册广告账户。竞品广告分析仅使用免费公开素材和公开资料。
8. **不伪造竞品买量数据。** 不得编造竞品消耗、CTR、CPC、CPA、ROI、真实玩家付费、真实 DAU 或小时活跃人数。
9. **不夸大数据源能力。** 网站链接可访问不代表 API 已接通；来源进入目录不代表已获授权；第三方榜单不代表官方经营数据。
10. **保持技术简单。** 第一版优先一个后端、一个 SQLite 数据库和一个定时同步入口；不做微服务、大数据仓库、多模型工作流或复杂任务队列。
11. **保留已有素材。** 当前网站已有游戏案例、图片记录和 GIF 动作素材。开发前必须清点并保留可用素材、来源和授权状态，不得因重构而丢失。
12. **未经用户明确确认，不发布 V2.0 到当前生产网址。** 开发完成先提供预览和验收结果，由用户决定是否替换线上版本。

# 1. 产品定位与最终目标

## 1.1 产品定位

GAME ART INTELLIGENCE 是一个面向微信、抖音轻度和中度小游戏的市场情报、用户研究、竞品创意分析、美术趋势研究与研发决策平台。

它不是单纯的游戏截图网站，也不是单纯的排行榜。

核心研究链路：

**市场发现 → 游戏研究 → 用户画像 → 吸量／创意分析 → 玩法与美术分析 → 趋势判断 → 研发建议。**

## 1.2 网站必须回答的核心问题

### 市场
- 现在什么小游戏最值得关注？
- 哪些游戏正在上升，哪些正在下降？
- 哪些玩法或题材开始出现连续增长信号？
- 哪些方向已经成熟、竞争加剧或可能饱和？
- 微信和抖音市场有哪些差异？

### 用户
- 这些游戏可能吸引什么用户？
- 用户为什么会点击、尝试和持续游玩？
- 用户追求解压、爽感、收集、成长、社交还是情绪价值？
- 相关内容受众和实际玩家是否有区别？

### 研发
- 哪些玩法、题材值得研究？
- 哪些新美术风格有差异化机会？
- 什么视觉包装更适合目标用户和平台？
- 下一款产品应该先验证什么，而不是直接照抄哪款热门游戏？

## 1.3 目标用户与产品范围

重点：微信小游戏、抖音小游戏、轻度游戏、中度游戏、轻中度融合产品。

不以大型端游、主机游戏或传统重度手游为主要研究对象。其他平台产品只可作为辅助视觉参考，必须明确标注。

# 3. 页面详细需求

## 3.1 市场总览 MARKET（首页）

首页是老板最常看的页面。首屏必须先展示市场信号和机会，而不是大段品牌介绍或重复游戏截图。

### 首屏
- 网站名称：GAME ART INTELLIGENCE
- 简短副标题：小游戏市场机会与美术趋势研究
- 搜索框：可搜索游戏、玩法、题材、美术风格、发行商
- 平台切换：全市场／微信／抖音
- 数据日期、最近成功同步时间、数据覆盖范围

### 市场概览
只展示真实取得的数据：
- 微信榜单变化
- 抖音榜单变化
- 今日排名改善游戏
- 新进入当前观察范围的游戏
- 连续改善候选
- 已关注游戏

### 趋势观察
分成四种状态：
- **上升观察：** 有连续排名改善或其他独立信号支持。
- **新兴创新：** 新玩法、新题材或新美术表现，尚未形成成熟商业趋势。
- **成熟赛道：** 有多个已验证产品，但需要研究差异化。
- **竞争预警：** 产品或素材同质化、同类产品密集等信号增加。

### 机会卡片
每张卡片只显示：
- 游戏／玩法名称
- 一张有来源的代表画面（若有）
- 平台
- 当前排名及数据日期（若有）
- 7 日变化（历史足够时）
- 核心玩法／题材
- 趋势状态
- 一句话入选理由
- 进入详情链接

### 未来机会预览
展示未来 3／6／12 个月研究方向入口。每条方向必须能查看依据、案例、风险和置信度说明。不得展示无回测依据的“爆款概率”。

## 3.2 游戏数据库 GAMES

### 搜索
支持搜索：
- 游戏名称
- 玩法
- 题材
- 美术风格
- 发行商
- 平台

### 筛选
平台：微信、抖音、双平台。  
玩法：消除、合成、塔防、经营、模拟、Roguelike、射击、解谜、收纳及其他。  
题材：东方幻想、西方奇幻、现代生活、末日、科幻、历史、休闲治愈等。  
美术：2D 卡通、3D 卡通、Low Poly、Q 版、写实、手绘、像素、黏土质感、微缩模型等。  
趋势：上升、稳定、下降、新进入观察范围、创新观察。

标签没有可靠来源时允许人工研究备注，但必须标明“人工判断／待验证”。

### 列表字段
游戏名称、图标／截图、平台、榜单、当前排名、1 日变化、7 日变化、连续改善天数、玩法、题材、美术标签、数据日期、关注按钮。

没有数据的字段显示“暂无数据”，不能编造或填 0。

## 3.3 单游戏详情 GAMES / GAME PROFILE

每款游戏只建立一份主档案。所有页面调用同一份记录。

详情页分为六个区域：

### A. 基础资料
- 游戏名称
- 平台版本
- 游戏图标、真实游戏截图
- 发行商／开发商（有来源时）
- 上线时间（有来源时）
- 官方链接
- 核心玩法
- 题材
- 变现方式（有证据时）

### B. 市场表现
- 当前排名
- 历史排名曲线
- 近 7／30／90 日变化（历史足够才显示）
- 连续改善情况
- 新进入／重新进入观察范围记录
- 来源、榜单、覆盖范围和数据日期

### C. 用户画像
- 实际玩家画像（有实际玩家数据时）
- 相关内容受众画像
- 广告受众／定向资料
- 行业报告／调查样本
- 用户兴趣、需求、情绪动机、游玩场景
- 证据来源和样本时间

必须区分“实际玩家”和“内容受众”。不能把看过某类短视频的人直接写成某款游戏玩家。

### D. 公开吸量／广告创意研究
- 公开素材链接或截图
- 素材类型
- 开场钩子
- 玩法展示
- 视觉吸引点
- 目标用户假设
- 素材首次观察日期、最近观察日期
- 广告展示内容与实际玩法是否一致

没有真实账户数据时，只做公开创意分析，不显示竞品真实消耗、CTR、CPA、ROI。

### E. 美术与动作特效
- 角色设计
- 场景设计
- UI 设计
- 色彩体系
- 材质与渲染
- 构图与视觉辨识度
- 普通攻击
- 技能特效
- 命中特效、爆炸、粒子、镜头、受击反馈
- 现有 GIF 素材
- 图片来源与使用授权状态

### F. 研发参考
- 值得借鉴的部分
- 不建议直接复制的部分
- 用户需求机会
- 玩法创新空间
- 美术差异化空间
- 制作复杂度和研发风险
- 建议继续研究／小规模测试／持续观察／暂不推荐
- 判断依据和待验证事项

## 3.4 机会观察 OPPORTUNITIES

### 潜力游戏观察名单
可配置观察区间，例如第 30—200 名，但前提是数据源实际覆盖该范围。若只有 TOP20，必须明确显示“当前只覆盖 TOP20”，不得推断 21—200 名。

观察信号：
- 近 7 日排名改善
- 连续改善天数
- 新进入观察范围
- 重新进入观察范围
- 多平台表现改善
- 独立传播／投放信号（有证据时）

每个候选必须显示“为什么进入名单”，且可追溯原始数据。

### 新兴玩法与题材
可建立待验证研究标签：
- 消除＋经营
- 合成＋养成
- 塔防＋Roguelike
- 轻射击＋成长
- 排序／收纳＋收集
- 玩法＋剧情／装扮
- 其他经实际案例发现的融合玩法

不得因为标签被列出就称其已成为趋势。

### 新兴美术创新
观察方向可包括：
- 拼豆、沙画、手作质感
- 黏土、布艺、纸艺、拼贴
- 微缩玩具世界
- 东方民俗与志怪
- 非传统卡通材质
- 新型视觉反馈和动作特效

每个方向要有：案例、玩法、目标用户假设、视觉特点、市场竞争、创新空间、制作风险、下一步验证方式。

### 红海／竞争预警
观察同类产品密度、相似玩法、素材同质化、榜单表现和新产品进入情况。若市场覆盖不完整，必须写“在当前样本范围内竞争增加”，不得宣称全市场饱和。

### 未来趋势预测
按未来 3／6／12 个月整理研究判断。每项必须包含：
1. 研究方向
2. 当前市场证据
3. 代表游戏
4. 用户需求
5. 竞争情况
6. 玩法机会
7. 美术机会
8. 平台适配假设
9. 研发成本和风险
10. 下一步验证动作
11. 置信度及其理由
12. 什么新证据可能推翻判断

结论只允许：推荐继续研究／建议小规模测试／持续观察／暂不推荐。没有回测前不展示“爆款概率”。

## 3.5 用户与创意 AUDIENCE & CREATIVE

### 用户画像研究
按四类证据分别保存：
1. 实际玩家画像
2. 相关视频／题材内容受众画像
3. 广告受众或定向资料
4. 行业报告／调查样本画像

每条资料要保存对象、统计时间、来源、样本和方法。评论用于理解喜好与抱怨，不用于编造年龄、性别比例。

### 免费公开创意研究
优先核验：
- 抖音创意加速器
- 抖音小游戏官方公开内容
- 腾讯广告创意中心（公开权限需实际验证）
- 其他免费公开、允许使用的广告素材页面

记录：游戏、平台、素材链接、素材类型、开场钩子、玩法、画面风格、用户假设、观察日期、来源。

分析：前 3 秒、视觉冲突、失败／成功对比、玩法演示、成长反馈、奖励反馈、治愈／解压／爽感／猎奇／剧情反转等。

### 买量数据边界
本项目目前没有自有抖音广告账户，也没有商业买量数据预算。
- 不接入自有广告账户。
- 不要求用户注册广告账户。
- 不开发自有账户 CTR／CPA／ROI 报表。
- 竞品只研究免费公开素材和公开信号。
- 素材数量、观察频率、投放天数不能换算成广告消耗。
- 真实竞品消耗、CTR、CPA、ROI、玩家充值和 DAU 不可见时必须留空。

未来若公司获得自有账户和授权数据，再单独增加“我的游戏投放”模块，不与竞品数据混用。

# 5. 数据指标与真实性规则

## 5.1 指标定义

| 指标 | 含义 | 规则 |
|---|---|---|
| 榜单排名 | 某平台、某榜单的相对位置 | 保存榜单类型、来源、日期、覆盖深度 |
| DAU | 某日按指定身份口径去重的活跃用户 | 明确账号／设备等去重口径 |
| 小时活跃 | 某小时窗口内去重活跃用户 | 不把小时人数相加当日活 |
| 当前在线 | 某一时点在线人数 | 需专门在线／会话统计 |
| 新增用户 | 按来源定义首次进入的用户 | 明确首次进入口径 |
| 玩家付费人数 | 指定窗口成功付费去重用户 | 与订单数分开 |
| IAP | 玩家为游戏支付的金额 | 明确退款、毛额／净额、币种 |
| IAA | 游戏广告变现收入 | 与玩家充值分开 |
| 买量消耗 | 厂商为获客支付的广告费 | 不等于玩家付费 |
| 素材数量／投放天数 | 公开观察到的推广信号 | 无金额来源不得换算成消耗 |
| 内容互动 | 视频／帖子公开互动 | 不换算成新增玩家或留存 |
| 留存 | 同一批用户后续是否回来 | 明确队列、间隔和口径 |

## 5.2 数据类型标签
统一使用：
- 官方授权经营数据
- 第三方统计／估算
- 榜单观测
- 传播信号
- 投放信号
- 人工研究资料

多来源的同一指标分别保存，不直接平均或覆盖。

## 5.3 缺失状态
- 该来源不提供
- 尚未接入
- 本期未在当前覆盖范围内观测到
- 同步失败
- 来源未更新
- 暂不具备比较条件
- 有效数值为 0

前六种不得填成 0。同步失败不得清空旧快照。

## 5.4 数据时间必须分开
- `source_updated_at`：来源声明的更新时间；没有则为空。
- `fetched_at`：本系统抓取／导入时间。
- `period_start`、`period_end`：指标实际统计窗口。
- `granularity`：day、hour、minute、snapshot 或 unknown。

不得把抓取时间冒充源数据更新时间，不得把 unknown 自动改成 day。

# 7. 趋势候选规则：透明、可解释，不做伪预测

## 7.1 基础计算
- 单日排名改善：前一日排名 − 当前排名；正数表示排名改善。
- 7 日净改善：7 天前排名 − 当前排名。
- 30／90 日变化：只有对应历史快照存在时计算。
- 连续改善：相邻自然日均有有效排名改善；缺失、持平或下降均中断。
- 新进入观察范围：当前快照出现，上一期完整且同覆盖范围快照未出现；不等于新上线。
- 本系统首次发现：本地第一次保存到；不等于正式发布日期。
- 重新入榜：过去曾出现、前期未在范围内、当前再次出现。

## 7.2 可比较前提
必须同平台、同榜单、同来源、同口径、日期明确，且两端均在真实覆盖范围内。覆盖深度变化时暂停新进／退出判断。

如果来源只提供 TOP20：
- 只显示 TOP20。
- 不推断第 21—200 名。
- 不把未观测当作排名 21 或 0。
- 不能宣称已经覆盖长尾潜力游戏。

## 7.3 多信号
若排名改善之外，还有独立的传播、投放、用户或内容证据，可以标记“多信号观察”。两个网站转载同一榜单不算两份独立证据。

## 7.4 趋势状态
- 上升观察
- 新兴创新
- 成熟赛道
- 竞争加剧
- 下降／风险观察
- 数据不足，暂不判断

每个候选必须显示触发理由、数据日期、来源和覆盖范围。

11. 用户内容受众不被标为实际玩家。
12. 没有广告账户时，自有 CTR／CPA／ROI 模块显示未启用。
13. API 密钥不出现在前端、公开仓库或公开数据文件。
14. 生产网站在用户批准前保持不变。
15. 页面没有重复游戏档案和重复介绍。
16. 原有可用图片、GIF、来源信息得到保留。

# 12. 最终产品原则

**市场趋势决定研究方向，用户画像决定产品定位，吸量创意研究帮助理解用户入口，美术和特效形成视觉差异化，持续监测验证研究结论。**

最终目标不是告诉管理层市场上有哪些游戏，而是帮助管理层判断：

- 现在应该研究什么？
- 为什么值得研究？
- 给谁做？
- 玩法和题材怎么组合？
- 美术和特效如何形成差异？
- 微信和抖音各自适合什么表达？
- 当前证据是否足够支持立项？
- 下一步应该用什么低成本测试验证？

**执行要求：先完成 P0，向用户提交验收结果，等待确认后再开始 P1。不得跳过阶段门槛，也不得未经批准替换当前线上网站。**
